# Documentation and Learning Workflow

## Project Decisions and Progress

- Confirmed project decisions are recorded in `docs/decisions/decision-log.md`.
- Requirements are maintained in `docs/requirements/requirements.md`.
- The project overview is updated when the agreed scope or core framing changes.
- Important milestones and meaningful documentation changes are committed to GitHub with descriptive commit messages.
- Unresolved questions and working assumptions must remain clearly labeled; proposals must not be presented as confirmed decisions.

## Learning Notes

Learning explanations are provided in the study conversation. At the end of each learning chapter, a structured set of lecture notes will be provided for the student to write independently.

Learning notes will not be added to this repository unless the student explicitly asks for that.

## Commit Convention

Use concise, meaningful messages, for example:

- `docs: record initial project scope`
- `docs: define default target and prediction horizon`
- `docs: add dataset assessment`
- `feat: implement applicant input validation`

Each commit should represent a coherent and understandable change.
